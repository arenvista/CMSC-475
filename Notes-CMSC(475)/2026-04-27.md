# Distributional Robustness

## Example Scenario
Consider a shift from dataset $A$ to dataset $B$.

A common example is training a model in a controlled lab setting and then deploying it in real-world applications, where the data distribution may differ.

- Example: CAD model airplane $\rightarrow$ real airplane

This illustrates a distribution shift: the model learns from one type of data but is expected to perform well on another, related but different, type of data.

# Domain Adaptation

Domain adaptation studies how to train a model on one domain and apply it to another, different domain.

## Setup

We learn a predictor
$$
f : \mathcal{X} \to \mathcal{Y}, \qquad \hat{y} = f(x).
$$

A standard setting is:
- **Source domain**: labeled training data $\{(x_i^{src}, y_i^{src})\}$
- **Target domain**: test inputs $\{x_j^{tgt}\}$, often from a different distribution

## Goal

We want the model to perform well on the **target** domain. Formally, we aim to minimize the expected prediction loss on target data:
$$
\min_f \; \mathbb{E}_{(x,y) \sim P_{tgt}}\big[c(f(x), y)\big].
$$

Here:
- $c(\cdot, \cdot)$ is a loss function
- $P_{tgt}$ is the target-domain data distribution

## Main Challenge: Domain Shift

The core difficulty is that the training and test domains are different:
$$
P_{src}(X, Y) \neq P_{tgt}(X, Y).
$$

Equivalently,
$$
\underbrace{\text{source domain}}_{\text{train}} \neq \underbrace{\text{target domain}}_{\text{test}}.
$$

So even if a model performs well on the source domain, its performance may degrade on the target domain unless we adapt it to the distribution shift.

# Domain Adaptation Settings

Assume we have labeled samples from a **source domain** distribution $Q_{x,y}$:

$$
\mathcal{D}_S = \{(x_i^S, y_i^S)\}_{i=1}^{n_S}
$$

The goal is to learn a model that performs well on a **target domain**, whose distribution differs from the source.

## Target-domain scenarios

### 1. Unsupervised Domain Adaptation
We have **only unlabeled target samples**:

$$
\mathcal{D}_T = \{x_i^T\}_{i=1}^{n_T}
$$

In this setting, target labels are not available during training.

### 2. Semi-Supervised Domain Adaptation
We have a mixture of **many unlabeled** and **a few labeled** target samples:

$$
\mathcal{D}_T^{(u)} = \{x_i^T\}_{i=1}^{n_u}, \qquad
\mathcal{D}_T^{(l)} = \{(x_i^T, y_i^T)\}_{i=1}^{n_l}
$$

This setting is easier than the fully unsupervised case because some target supervision is available.

### 3. Domain Generalization
We have **no target samples at all** during training.

The objective is to learn from one or more source domains in a way that generalizes to unseen target domains.

## How to approach each setting

### Unsupervised Domain Adaptation
Since target labels are unavailable, methods usually try to reduce the gap between source and target domains while still learning the prediction task on the source labels.

Common strategies include:
- **Feature alignment:** learn representations where source and target look similar.
- **Adversarial training:** use a domain discriminator so features become domain-invariant.
- **Distribution matching:** minimize distances such as MMD, CORAL, or related divergence measures.
- **Self-training / pseudo-labeling:** assign temporary labels to target examples and retrain.
- **Consistency regularization:** encourage stable predictions under perturbations or augmentations.

### Semi-Supervised Domain Adaptation
Here we can combine adaptation techniques with the few labeled target examples.

Typical strategies include:
- **Fine-tuning on labeled target data** after pretraining on the source domain.
- **Joint training** on source-labeled and target-labeled samples.
- **Pseudo-labeling** for unlabeled target examples, using the labeled target set to guide confidence.
- **Consistency regularization** on unlabeled target data.
- **Class-aware alignment:** align domains while preserving class structure using the available target labels.

Compared with unsupervised adaptation, the labeled target samples help resolve ambiguity and usually improve performance.

## Summary
- **Unsupervised domain adaptation (UDA):** the source domain is labeled, while the target domain is unlabeled.
- **Semi-supervised domain adaptation (SSDA):** the source domain is labeled, and the target domain contains both labeled and unlabeled examples.
- **Domain generalization (DG):** the source domain is labeled, and no target data is available during training.

# Domain Shift
A common assumption in the literature is **covariate shift**, where the input distributions differ between source and target domains:
$$
p_t(x) \neq p_s(x)
$$
while the labeling function is assumed to remain similar:
$$
p_t(y \mid x) \approx p_s(y \mid x)
$$

In other words, the kinds of inputs seen at test time differ from those seen during training, even if the underlying prediction task is the same.

## Common approaches for handling covariate shift
- **Importance weighting / reweighting:** weight source samples so the reweighted source distribution better matches the target distribution.
- **Feature alignment:** learn a representation in which source and target features are closer, for example through adversarial alignment or discrepancy minimization.
- **Domain-invariant representation learning:** learn features that preserve task-relevant information while removing domain-specific variation.
- **Self-training / pseudo-labeling:** generate labels for target samples and iteratively adapt the model.
- **Normalization or style transfer methods:** transform inputs so that source and target appear more similar.
- **Optimal transport:** explicitly map the source distribution onto the target distribution.

## How do we determine what transformation to apply?
In practice, the transformation is usually **not known in advance**. Instead, it is estimated from data by making the source and target domains more similar under some criterion.

Common strategies include:
- **Distribution matching:** choose a transformation that minimizes a discrepancy measure such as MMD, Wasserstein distance, or KL divergence.
- **Adversarial learning:** train a feature extractor so a domain classifier cannot distinguish source from target features.
- **Moment matching:** align low-order statistics such as means and covariances between domains.
- **Learned mappings:** use neural networks, optimal transport, or generative models to learn a mapping from source samples to target-like samples.
- **Task-aware adaptation:** prefer transformations that both align domains and preserve predictive performance on labeled source data.

## Practical intuition
The goal is not necessarily to recover the exact physical transformation from source to target. Rather, the goal is to learn a representation or mapping such that:
1. source and target samples become comparable, and
2. a predictor trained on the source still performs well on the target.

So, in most machine learning settings, we infer the transformation indirectly by optimizing an objective that balances **domain alignment** and **task performance**.

# How to Learn Generalizable Representations

## Regularization
Use a regularizer to align representations across domains so that the model learns features that transfer beyond a single training distribution.

- Encourage embeddings from different domains to occupy a similar feature space.
- Reduce domain-specific shortcuts that hurt out-of-distribution performance.
- Improve robustness by favoring invariant structure over superficial correlations.

Common approaches include contrastive objectives, adversarial domain alignment, distribution matching penalties, and consistency regularization.

# How to Learn Generalizable Representations
## Regularization
$$
    \min_{\theta} \; \mathbb{E}_{(x,y) \sim \mathcal{D}}\big[\mathcal{L}(f_{\theta}(x), y)\big] + \lambda \, \Omega(\theta)
$$
> [!pf]- Explanation of Variables
> - $\theta$: the model parameters being optimized
> - $x$: an input example
> - $y$: the target label or ground-truth output for $x$
> - $\mathcal{D}$: the data distribution (or dataset) that input-output pairs $(x,y)$ are drawn from
> - $f_{\theta}(x)$: the model's prediction for input $x$ using parameters $\theta$
> - $\mathcal{L}(f_{\theta}(x), y)$: the loss function, measuring how far the prediction is from the target
> - $\mathbb{E}_{(x,y) \sim \mathcal{D}}[\cdot]$: the expected value over examples sampled from the data distribution
> - $\Omega(\theta)$: a regularization term that penalizes undesirable parameter values (for example, overly large weights)
> - $\lambda$: a regularization coefficient that controls how much the regularization term influences the objective
> - $\min_{\theta}$: choose the parameter values $\theta$ that make the entire objective as small as possible
